Slicemeter Architecture & Non-Obtrusive Security Model ​

This document outlines the architectural design and security principles of Slicemeter: the GPU FinOps & Token Chargeback engine for Kubernetes.

1. Core Principles: Non-Obtrusive by Default ​

Enterprise platforms and Kubernetes security administrators are rightfully cautious regarding cluster-wide mutations and elevated permissions. Slicemeter enforces a strict non-obtrusive baseline:

  1. Zero Workload Mutation Default: Slicemeter defaults to passive DCGM metric scraping via Prometheus and/or eBPF tracing. It does NOT mutate workloads, inject sidecars, or interfere with Pod specs unless explicitly requested.
  2. Explicit Opt-In Sidecar Injection:
  • The MutatingWebhookConfiguration is disabled by default in Helm (webhook.enabled: false).
  • Even when enabled, the namespace selector enforces explicit admin labeling (slicemeter.io/injection: enabled).
  • Teams can manually annotate workloads (slicemeter.com/inject-sidecar: "true") without deploying mutating webhooks.
  1. Non-Blocking Safety Net: The admission webhook specifies failurePolicy: Ignore and a strict timeoutSeconds: 5. If the Slicemeter webhook pod is unreachable or failing, Kubernetes never blocks Pod creation.
  2. Least-Privilege RBAC:
  • Slicemeter agent requires read-only permissions (get, list, watch) across Nodes, Pods, and Namespaces.
  • Zero ClusterAdmin or write capabilities are requested in default installs.

2. Telemetry Architecture & eBPF Fallbacks ​

eBPF Precision Mode vs DCGM Fallback Mode ​

  • DCGM Fallback Mode (Default): Reads cluster metrics passively via Prometheus. Requires zero kernel dependencies and zero elevated Linux capabilities. Works 100% out of the box across Azure AKS, AWS EKS, Google Cloud GKE, and self-managed Kubernetes.
  • eBPF Precision Mode (Opt-In): Attaches uprobes to libcudart.so / libcuda.so on Linux kernel 5.8+ with CAP_BPF & CAP_PERFMON. Attributes sub-second CUDA kernel execution directly to host PIDs and Kubernetes cgroups.

3. Storage Layer: Embedded BadgerDB & Distributed etcd ​

Slicemeter supports dual ledger backends depending on deployment topology:

  • Embedded BadgerDB (SLICEMETER_LEDGER_BACKEND=badger): Zero external state dependencies. Stores transaction logs directly inside the agent Pod persistent volume. Ideal for edge clusters, single-node setups, and managed Kubernetes (EKS/GKE/AKS).
  • Distributed etcd (SLICEMETER_LEDGER_BACKEND=etcd): Uses standard etcd storage for HA multi-agent deployments on self-managed clusters.

4. Hardened Security & Isolation Model ​

Slicemeter enforces a zero-trust, non-obtrusive security posture across all Kubernetes deployments:

Minimal Read-Only RBAC Boundaries ​

  • Zero Workload Mutation: Slicemeter ServiceAccounts hold strictly read-only cluster permissions.
  • Isolated API Groups: The agent cannot create, modify, or delete workload Pods, Deployments, or StatefulSets (apps/v1, core/v1).

Network Egress Lockdown ​

  • Egress Isolation: Enforces a strict NetworkPolicy restricting agent network egress strictly to the cluster API server and local Prometheus endpoints.
  • Zero Internet Egress in Air-Gap: No external phone-home calls, analytics pings, or license validation requests leave your infrastructure boundary.

Cryptographic TLS Cert Bootstrapping ​

  • ECDSA P-256 TLS Encryption: Automated in-cluster ECDSA P-256 certificate generation for all admission and telemetry endpoints.
  • Dependency-Free Security: Eliminates external cert-manager or secret injector dependencies.

Fail-Safe Admission Webhook Guarantee ​

  • Availability First: Configured with failurePolicy: Ignore to guarantee that API server availability and pod scheduling are never blocked, even if telemetry collection experiences temporary network degradation.

5. Multi-Tenant Enterprise Single Sign-On (SSO & OIDC) ​

Slicemeter Control Plane provides enterprise-grade identity federation across both hosted SaaS (app.slicemeter.com) and air-gapped on-premise deployments:

Standard Public SaaS Auth (app.slicemeter.com) ​

  • Developer & Starter Access: Work email/password authentication or 1-click GitHub OAuth 2.0.
  • Domain Auto-Routing: Enterprise organizations register their corporate domain (company.com). When employees log in via company.com, Slicemeter automatically redirects them to their corporate identity provider.

Self-Hosted Enterprise On-Premise Auth ​

  • OIDC & SAML 2.0 Protocol Support: Native integration with Microsoft Entra ID (Azure AD), Okta, Keycloak, Ping Identity, and Auth0.
  • Zero-Trust Identity Mapping: Maps corporate IdP SAML assertion claims (groups, roles) directly to Slicemeter RBAC roles (admin, finops, viewer).
